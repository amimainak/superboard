# SUPERBOARD — PHASEWISE CORRECTION PLAN
**Philosophy: Whiteboard is the center. Widgets are modular. Teachers compose. Templates persist. SDK-ready.**

---

## KEY ARCHITECTURAL DECISIONS (Before Phase 1 Starts)

### 1. Canvas Widget Rendering Strategy

tldraw supports **custom shapes** via `shapeUtils` — React components that live inside the tldraw document, participate in undo/redo, zoom/pan, and export. This is the correct path for L3 widgets.

The current "Add to Board" likely dumps a static image/asset. The new system will:

- Register each widget type as a **custom tldraw shape** with its own `shapeUtils`
- The shape renders a React component that handles its own pointer events
- Widget state (fraction parts, quiz answers, flashcard index) lives in `shape.props`
- tldraw's built-in move/resize handles the drag/resize — no custom drag code needed
- Docking = snapping widget bounds to canvas edges (top/bottom/left/right)

**Proof-of-concept widgets for Phase 1** (chosen for interaction diversity):
- **Interactive Quiz** — click-to-answer with instant feedback (most complex: state machine)
- **Fraction Circle** — click parts to shade/unshade (medium: visual state)
- **Flashcards** — click to flip, arrows to navigate (medium: animation + state)
- **Base-10 Blocks** — drag individual unit blocks on canvas (complex: multi-item drag)

### 2. Widget State Architecture

Every widget that goes on canvas needs a state schema:

```
CanvasWidget = {
  id: tldraw shape id
  type: 'fraction-circle' | 'quiz' | 'flashcard' | 'function-plotter' | ...
  props: { ...widget-specific state... }  // persists in tldraw document
  x, y, width, height, rotation  // handled by tldraw
  isLocked: boolean  // student mode prep (deferred)
}
```

Sidebar panel tools and canvas widgets share the **same React component** but receive props differently:
- Sidebar: props from local React state
- Canvas: props from `shape.props`, updated via `editor.updateShape()`

This means every existing panel tool can become a canvas widget by wrapping it in a custom shape — no rewrite needed for L1/L2.

### 3. Template Storage Model

Templates are **JSON documents** stored in Supabase (you already have it):

```
Template = {
  id: uuid
  owner_id: auth.user.id
  title: string
  description: string
  subject: 'MATH' | 'SCIENCE' | 'LANGUAGE' | 'ARTS' | 'GENERAL'
  grade_band: 'K-5' | '6-8' | '9-12'
  is_public: boolean  // sharing toggle
  snapshot: {
    widget_configs: [{ type, props }]  // what widgets, their settings
    canvas_layout: [{ type, x, y, w, h }]  // positions and sizes
    background: 'grid' | 'dot' | 'lines' | 'none'
    subject_filter: string  // which subject tab is active
  }
  created_at, updated_at
}
```

**Sharing model**: Teacher A marks template `is_public: true` → appears in a "Community Templates" browser filtered by subject/grade. No approval flow, no monetization. Just share. Teachers can "Use Template" which creates a copy in their personal library with their own modifications.

**Supabase tables needed**: `templates`, `template_favorites` (for future), `template_tags` (for search).

### 4. Phase Ordering Logic

The plan is ordered so each phase **unlocks** the next:
- Phase 1 unlocks all content phases (widgets can go on canvas)
- Phase 2 unlocks teacher workflows (save/share/reuse)
- Phases 3-5 can be worked on **in parallel** after Phase 2 (they're independent content domains)
- Phase 6 is deferred until Phases 1-5 are stable

## PHASE 1: CANVAS WIDGET FOUNDATION
**Goal**: Every panel tool can be placed on the canvas as a draggable, resizable widget. High-value widgets are fully interactive (L3) on canvas.

### Deliverables

**1A. Custom Shape System for Canvas Widgets**
- Create a `CanvasWidgetShape` base type in tldraw's shape system
- Build a `widgetShapeUtils` registry that maps widget types to their tldraw shape definitions
- Each widget shape wraps the existing React component and reads/writes state via `shape.props`
- Widgets inherit tldraw's native move, resize (by handles), rotate, and delete
- Docking: snap to canvas edges when within 20px (visual guide appears)

**1B. Universal "Add to Board" Button**
- Add "Add to Board" to every single panel tool that's missing it (currently ~60% have it)
- Button behavior:
  - Click → creates a canvas widget shape at a smart default position (next to last placed widget, or center if first)
  - Auto-opens the widget at a reasonable default size (varies by widget type)
  - Sidebar stays OPEN (remove the 1.5s auto-collapse)
- Widgets placed on canvas default to L2 (live sync with sidebar) when possible
- Sidebar and canvas widget stay in sync: changing fraction parts in sidebar updates canvas and vice versa

**1C. L3 Interactive Canvas Widgets (Proof of Concept)**
Implement full interactivity on canvas for these 4 widgets:

| Widget | Interaction | Complexity |
|--------|------------|------------|
| **Interactive Quiz** | Click answer choice → instant correct/incorrect feedback → next question → final score | High |
| **Fraction Circle** | Click individual segments to shade/unshade → visual updates instantly | Medium |
| **Flashcards** | Click to flip → arrow navigation → shuffle | Medium |
| **Base-10 Blocks** | Stamps panel gets ones/tens/hundreds/thousands blocks → drag onto canvas → they snap together | High |

**1D. Widget Canvas Toolbar**
When a canvas widget is selected, show a floating mini-toolbar:
- Pin/Unpin (lock position)
- Duplicate
- Bring to Front / Send to Back
- Reset to Default
- Remove from Board
- (Future: "Lock for Students" — grayed out, prep for student mode)

**1E. Widget Panel UX Improvements**
- Make each tool section **collapsible** (accordion pattern) to reduce scrolling
- Add a "Minimize Panel" button that collapses the sidebar to icon-only (expandable on hover)
- Show a small indicator on sidebar tools that are already on the canvas (e.g., checkmark or dot)

### What This Unlocks
- Templates can save widget positions because widgets now HAVE positions
- All future widgets automatically get canvas placement via the shape system
- Teachers can compose lesson layouts by placing multiple widgets side by side
- The "Add to Board" inconsistency problem is solved permanently

### Complexity: High (2-3 weeks)
This is the heaviest phase because it changes the core architecture. But it's a one-time cost — everything after this is incremental.

## PHASE 2: TEMPLATE ENGINE
**Goal**: Teachers save their widget configurations and canvas layouts as reusable templates, and share them with peers.

### Deliverables

**2A. Template CRUD System**
- "Save as Template" button in the room toolbar → opens a modal:
  - Title (required), Description (optional)
  - Subject (auto-detected from current filter, editable)
  - Grade Band (auto-detected, editable)
  - Tags (comma-separated, for search)
  - "Make Public" toggle (default: off)
- "My Templates" panel accessible from room toolbar:
  - Grid of template cards showing title, subject icon, grade band, last modified
  - Search and filter by subject/grade
  - Edit title/description, duplicate, delete, toggle public/private
- "Start from Template" → loads the template into a fresh room

**2B. Template Sharing**
- "Community Templates" browser:
  - Filterable by subject, grade band, search query, tags
  - Sort by: newest, most used, most favorited (future)
  - "Use This Template" → creates a copy in personal library → opens in new room
  - "View Details" → shows description, widget list, preview thumbnail (optional)
- Template author attribution (shows creator name)
- No approval workflow. No monetization. Pure peer sharing.

**2C. Template Snapshot Format**
A template saves:
- Which widgets are on the canvas + their types and configurations
- Widget positions (x, y) and sizes (width, height)
- Canvas background type
- Active subject filter
- It does NOT save canvas drawings/content (that's session save, a different feature)

**2D. Supabase Backend**
- `templates` table (id, owner_id, title, description, subject, grade_band, tags, is_public, snapshot JSONB, created_at, updated_at)
- RLS policies: users can read/write their own; everyone can read public templates
- `template_tags` table for normalized tag search (optional, can start with comma-separated string in tags column)

**2E. Quick-Template Keyboard Shortcut**
- `Ctrl/Cmd + Shift + S` → Save current room as template (opens the modal)
- `Ctrl/Cmd + Shift + T` → Open template browser

### What This Unlocks
- Teachers don't set up from scratch every session
- Community grows organically — good templates spread
- Subject leads / curriculum teams can standardize setups
- Future: template analytics (most-used, highest-rated)

### Complexity: Medium (1-2 weeks)
Mostly CRUD + JSON serialization. The snapshot format is the main design decision.

## PHASE 6: PLATFORM FEATURES & FUTURE (DEFERRED)
**Goal**: Transform from a tutoring tool into a tutoring platform. These are not needed until Phases 1-5 are stable.

### 6A. Student Mode (Deferred per your request)
- Toggle in room toolbar: "Enable Student Mode"
- When enabled: hides panel, locks tutor annotations, makes only designated canvas widgets interactive
- Student sees: canvas with interactive widgets + a "Raise Hand" / "I'm Confused" button
- Tutor sees: same canvas + student status indicators
- Permission levels: view-only, interact-with-widgets, draw

### 6B. Session Recording & Playback
- Record all canvas actions as a timeline
- Playback at 1x/2x/4x speed
- Share recording link with absent students
- Export as video (optional, higher effort)

### 6C. Student View / Preview Mode
- "Preview as Student" button for tutors
- Shows exactly what a connected student would see
- Useful for lesson prep and QA

### 6D. Progress Tracking
- Mark standards covered in a session (Common Core / NGSS / state standards)
- Per-student session history
- "Standards Covered This Week" dashboard for tutors
- Optional: student performance from assessments

### 6E. Widget Communication API
- Define a `widgetBus` event system so widgets can talk to each other
- Examples: Function Plotter sends graph → Assessment widget creates a question about it
- Data Collection Table sends data → Bar Chart widget renders it
- This is the foundation for the "smart tutoring" experience

### 6F. SDK Extraction Prep
- Decouple whiteboard + widget system from the hosting app
- Extract into a standalone npm package: `@superboard/core`
- API: `createBoard(container, { widgets, templates, auth, collaboration })`
- The Phase 1 canvas widget architecture (custom tldraw shapes) makes this clean — the SDK is essentially: tldraw + widget shape registry + template system + collaboration layer

### Complexity: Very High (4-6 weeks total)
This is effectively a separate product phase. Start only after Phases 1-5 are shipped and stable for at least 2 weeks of real usage.
